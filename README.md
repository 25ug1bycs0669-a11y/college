# CampusFlow College Management System

A responsive college administration portal with a React dashboard, Express REST API, and MySQL persistence. The project includes role-based sign-in, student/faculty/course/department management, daily attendance, fee tracking and printable receipts, examinations and grades, conflict-checked class schedules, CSV exports, and light/dark themes.

## Requirements

- Node.js 20 or newer and npm
- MySQL 8.0 or newer, running locally or reachable from the backend

## Run locally (Windows / VS Code)

Open the project folder in VS Code and use its integrated PowerShell terminal:

1. Create the database and tables:

   ```powershell
   Get-Content .\backend\database\schema.sql -Raw | mysql -u root -p
   ```

   Enter your MySQL password when prompted. If `mysql` is not on your PATH, run the equivalent command with the full path to `mysql.exe`.

2. Create the backend environment file:

   ```powershell
   Copy-Item .\backend\.env.example .\backend\.env
   ```

   Edit `backend\.env` and set your MySQL credentials and a private, random `JWT_SECRET`. The example secret is for local setup only; replace it before use.

3. Install dependencies, add the sample records/accounts, and start both servers:

   ```powershell
   npm install
   npm run seed
   npm run dev
   ```

4. Open [http://localhost:5173](http://localhost:5173). The API health check is at [http://localhost:4000/api/health](http://localhost:4000/api/health).

The seed command is safe to rerun for its sample records. It creates these local demonstration accounts:

| Role | Email | Set password with |
|---|---|---|
| Admin | `admin@college.edu` | `SEED_ADMIN_PASSWORD` |
| Faculty | `priya.faculty@college.edu` | `SEED_FACULTY_PASSWORD` |
| Student | `aarav.student@college.edu` | `SEED_STUDENT_PASSWORD` |

Set each seed password to a private value of at least 12 characters in `backend/.env` before running the seed command. The seed script intentionally resets those account passwords whenever it is run. No usable passwords or tokens are committed to the project.

## Commands

Run these at the project root:

| Command | Description |
|---|---|
| `npm run dev` | Run the API (`:4000`) and Vite frontend (`:5173`) together |
| `npm run build` | Create the frontend production build in `frontend/dist` |
| `npm start` | Run the API in production mode |
| `npm run seed` | Insert sample academic records and demo accounts |

The frontend uses `VITE_API_URL` if set; otherwise it calls `http://localhost:4000/api`. The API reads database, CORS, and token settings from `backend/.env`.

## Features and access

- **Admin:** create, search, update, and delete student, faculty, course, department, and exam records; manage attendance, fee records/payments, results, and timetable.
- **Faculty:** view the faculty schedule, review student records, mark attendance, and enter examination results.
- **Student:** view their own profile, fee history, course information, examination results, and course timetable. Student fee/profile records are scoped to the signed-in email.
- Student and faculty IDs are generated by the API. Course and department references are validated by MySQL foreign keys.
- Attendance can be filtered by date, department, and student. Marking the same student twice on a date updates that day's record.
- Timetable entries reject overlapping times for the same room or faculty member on the same day.
- Fee receipts open the browser print dialog; select **Save as PDF** to download a PDF receipt. Management and attendance views export CSV reports.
- Login passwords use bcrypt hashes, API sessions use signed JWTs, login attempts are rate-limited, and write endpoints enforce roles on the server.

## REST endpoints

All endpoints below are prefixed with `/api`. Except for health and sign-in, requests require `Authorization: Bearer <token>`.

| Endpoint | Methods / purpose |
|---|---|
| `/health` | API health check |
| `/auth/login`, `/auth/me`, `/auth/users` | Sign in, current account, admin-created account |
| `/dashboard` | Dashboard totals, attendance, fees, recent students, and chart data |
| `/students`, `/faculty`, `/courses`, `/departments`, `/exams` | List and admin CRUD |
| `/attendance` | Filter and mark attendance |
| `/fees`, `/fees/:id/pay` | View/create fee records and record payment |
| `/exams/:id/results` | Read and upsert examination results with calculated grades |
| `/timetable` | View, create, and remove class schedule entries |

## Production notes

Set `CLIENT_ORIGIN` to the deployed frontend origin, use a unique high-entropy `JWT_SECRET`, and configure a least-privilege MySQL account. Serve the built `frontend/dist` from a static host and deploy the API separately. Demo credentials and sample records are for local development and must not be used for real student data.
